# Сборка и прошивка
English version: **[BUILD.md](BUILD.md)**

Проект — обычный проект [PlatformIO](https://platformio.org/): никаких своих скриптов и вендоренных библиотек, всё нужное лежит в репозитории.



## Что нужно

- [PlatformIO Core](https://docs.platformio.org/en/latest/core/installation/) 6.x
  (`pip install platformio` или расширение PlatformIO для VS Code)
- Python 3.8+ (идёт вместе с PlatformIO)
- Плата ESP32-C3 с **4 МБ flash** и подключением по USB

Зависимости подтягиваются сами: `olikraus/U8g2 @ ^2.34.14`, платформа
`espressif32` и фреймворк Arduino.

## Готовый образ (без PlatformIO)

Если нужно просто запустить устройство, прошейте готовый образ из репозитория —
из инструментов понадобится только `esptool`:

```bash
esptool.py --chip esp32c3 --baud 460800 write_flash 0x0 clickerbot-2.1-diy-merged.bin
```

Файл лежит в [`firmware/`](../firmware/README.ru.md) вместе с контрольной суммой
SHA-256 и альтернативой для Windows с графическим интерфейсом (Flash Download
Tool от Espressif). Это та же сборка, что делает CI из этого репозитория —
версия `2.1-diy`.

## Сборка

```bash
pio run              # сборка
pio run -t clean     # очистить каталог сборки
```

Результат появляется в `.pio/build/esp32-c3-devkitm-1/`:

| Файл | Адрес во flash | Размер (v2.1-diy) |
|---|---|---|
| `bootloader.bin` | `0x0` | ~12 КБ |
| `partitions.bin` | `0x8000` | 3 КБ |
| `firmware.bin` | `0x10000` | ~900 КБ |

Текущий расход приложения: **883 КБ из 2,5 МБ** app-раздела (33,7 %),
**49 КБ RAM** (15,1 %).

Сборка сообщает версию `2.1-diy` в баннере UART, и та же строка лежит в бинарнике
как `CLICKERFW:2.1-diy` (удобно, когда сообщаете о проблеме).

## Прошивка по USB

```bash
pio run -t upload
pio device monitor -b 115200
```

Если заливка обрывается по таймауту ожидания чипа, переведите плату в режим
загрузчика вручную: удержите кнопку меню (`BOOT`), нажмите `RESET`, отпустите
`RESET`, затем отпустите `BOOT`. Прошивка помогает и здесь: удержание кнопки меню
5 с рисует статичный экран «готов к прошивке», который переживает `RESET` (см.
[HARDWARE.ru.md](HARDWARE.ru.md#прошивка-чипа)).

## Прошивка без PlatformIO (`esptool`)

```bash
esptool.py --chip esp32c3 --baud 460800 write_flash \
  --flash_mode dio --flash_freq 40m --flash_size 4MB \
  0x0     bootloader.bin \
  0x8000  partitions.bin \
  0x10000 firmware.bin
```

Или соберите единый образ и залейте его по адресу `0x0`:

```bash
esptool.py --chip esp32c3 merge_bin -o clickerbot-2.1-diy-merged.bin \
  --flash_mode dio --flash_freq 40m --flash_size 4MB \
  0x0 bootloader.bin 0x8000 partitions.bin 0x10000 firmware.bin

esptool.py --chip esp32c3 --baud 460800 write_flash 0x0 clickerbot-2.1-diy-merged.bin
```

Оба варианта не трогают раздел `nvs`, поэтому счётчики кликов, ник и сохранённые
сети Wi-Fi переживают обновление. `erase_flash` нужен только если вы
действительно хотите сбросить устройство к заводскому состоянию.

## Разметка flash

`partitions.csv` объединяет два OTA-слота штатной схемы `default` в один
app-раздел на 2,5 МБ (OTA в прошивке нет):

| Имя | Тип | Адрес | Размер |
|---|---|---|---|
| `nvs` | data/nvs | `0x9000` | 20 КБ |
| `otadata` | data/ota | `0xe000` | 8 КБ |
| `app0` | app/factory | `0x10000` | 2,5 МБ |
| `spiffs` | data/spiffs | `0x290000` | 1,4 МБ (не используется, зарезервирован) |

> Не подставляйте другую таблицу разделов: приложение слинковано под эту
> разметку, и в меньший app-раздел сборка уже не влезет.

## Правило 40 МГц + DIO

`platformio.ini` жёстко задаёт:

```ini
board_build.flash_mode = dio
board_build.f_flash = 40000000L
```

**Не поднимайте до 80 МГц.** Модули ESP32-C3 с безымянной микросхемой flash
(JEDEC-ID `0x464016`, попадались на 4 МБ) прекрасно грузятся на 80 МГц, но из
приложения больше не могут стирать и записывать flash: устройство работает; но
ничего не сохраняется — NVS даже не может создать namespace, поэтому счётчики
остаются нулями, а настройки Wi-Fi не записываются. ROM-чтение в таком состоянии
может ещё и подвесить чип до перезагрузки.

40 МГц в режиме DIO — самая совместимая конфигурация, и ровно так же общается с
flash ROM-загрузчик, поэтому для самодельного железа это безопасный вариант по
умолчанию.

## Непрерывная сборка

`.github/workflows/build.yml` собирает прошивку на каждый push и pull request и
выкладывает `firmware.bin` как артефакт сборки. Если правка ломает сборку, это
видно по статусу CI ещё до того, как кто-то прошьёт устройство.

## Если что-то не работает

| Симптом | Вероятная причина |
|---|---|
| Устройство работает, но счётчики и настройки Wi-Fi не сохраняются | та самая проблема с микросхемой flash — проверьте `board_build.flash_mode` / `f_flash` и реальный JEDEC-ID через `esptool.py flash_id` |
| При заливке `Timed out waiting for packet header` | чип не в режиме загрузчика: удержите `BOOT`, нажмите `RESET`, отпустите и повторите |
| В мониторе порта ничего нет | `Serial` — это UART0 (TX на `GPIO21`); на плате с родным USB добавьте `-D ARDUINO_USB_CDC_ON_BOOT=1` |
| Экран остаётся чёрным | проверьте `SDA = GPIO5`, `SCL = GPIO6` и адрес I2C (`0x3C` по умолчанию, `0x3D` на части модулей) |
| Заряд всегда 100 % или 0 % | средняя точка делителя должна идти на `GPIO0`, низ делителя — на `GPIO20` |
| Устройство перезагружается по кругу после пробуждения | аккумулятор почти пуст — см. обработку критического уровня в `Config.h` |
